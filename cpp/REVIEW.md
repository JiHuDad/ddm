## 요약

**"드리프트를 감지하는 센서"는 완성도가 높지만, 센서가 울린 다음의 이야기(대응·재학습 루프의
재료)가 비어 있고, 센서 자체에도 실전 배포에서 걸릴 구멍이 있다.**

| 층 | 상태 |
|---|---|
| 탐지 메커니즘 (탭→shm→worker) | ✅ 무할당 hot-path 증명, 동시성 무손실 증명, E2E |
| 탐지 알고리즘 (PSI/KS/CUSUM/ADWIN) | ✅ 동작 (일부 단순화 변형) |
| 운영 반출 (export) | 🟡 파일 sink까지 |
| 탐지 이후 (알람→대응→재학습) | ❌ 이번 보강의 핵심 |

## 발견된 공백 (코드 확인 완료)

- **A1 (🔴)** 탭 재연결 없음 — `tap_init` 1회 시도. worker가 늦게 뜨거나 번들 갱신으로 arena가
  재생성되면 서빙 재시작 전까지 감시 공백. *조용히* 죽는 것이 최악.
- **A2 (🔴)** 서빙 프로세스당 모델 1개만 탭 가능 (`g_tap` 전역 1개). worker는 다모델인데 비대칭.
- **A3 (🟡)** NaN이 조용히 사라짐 (`tap_hot.cpp` `continue`) — NaN 비율 자체가 전처리 고장
  신호인데 미집계. 범위 이탈(underflow/overflow)은 세면서 값 손상은 안 셈 → 비일관.
- **A4 (🟡)** severity 경계 하드코딩(worker_main 0.1/0.2, "수치는 번들에서" 원칙 위반) +
  디바운스 없음 → 임계 근처 알람 폭풍.
- **A5 (🟡)** 단변량 한정 — 피처 간 상관 붕괴는 못 봄 (tier-1 트레이드오프, 한계 명시 필요).
- **A6 (🟢)** 번들 hot-reload 없음 / ADWIN 단순화 / KS 비통계 임계 / `mode_tag` 미사용
  (시간대별 reference 전환 의도 미구현) / RT 실측·장기 soak 미수행.

## Data drift 외 추가 모니터링 (4계통 관점)

| 계통 | 현재 | 판단 |
|---|---|---|
| ① 입력 드리프트 | ✅ | — |
| ② 출력/예측 드리프트 | 🟡 탭은 있으나 E2E 미검증. **신뢰도(엔트로피) 채널 권장** — 라벨 없이 concept drift를 가장 싸게 근사 | 보강 |
| ③ 데이터 품질 | ❌ NaN율·이탈률·상수화 — **실무 오탐의 절반은 파이프라인 고장** | 최우선 |
| ④ 성능/운영 (지연·QPS·에러) | 서빙 인프라 몫으로 선 긋기 (QPS만 export에 무료 포함) | 범위 밖 |

+ **모니터링의 모니터링**: 탭 생존(샘플 유입률), export staleness. no-op degrade가 조용히
  일어나는 현 구조에서 필수.
+ 개념 드리프트(ground-truth)는 tier-2/3(off-box) 유지가 옳다.

## Fine-tuning / Retraining 검토

현 시스템은 "화재 감지기"까지. 루프를 닫으려면:

- **R1 (🔴 치명)** 재학습할 *데이터*가 안 남는다 — 히스토그램에서 원본 복원 불가. 저비용
  샘플링(1/N → shm 링버퍼)으로 raw 피처 벡터 보존 + 알람 시 덤프가 없으면 자동 재학습 루프
  자체가 불성립.
- **R2** 드리프트 유형→대응 매핑: 급변(ADWIN)=원인조사→전체 재학습 / 점진(CUSUM)=fine-tune
  적합 / 경계 이탈=재학습+bin 재산출 / NaN 급증=재학습 금지(파이프라인 수리). 이 분류
  (`drift_kind`)를 export에 실어야 off-box 자동화 품질이 오른다.
- **R3** fine-tuning 함정: ①라벨 없는 self-training 오염(사람/GT 게이트 필수) ②파국적
  망각(reference 혼합 replay) ③기준선 이동 — fine-tune 후 **번들 재발급 필수**, 모델↔번들
  버전 원자적 동시 배포.
- **R4** 번들 수명주기: hot-reload + 탭 재연결(A1 선행) + `model_version` 연동.
- **R5** champion/challenger: 새 모델을 shadow로 돌리며 새 번들 기준 무드리프트를 배포
  게이트로 — 코드 추가 없이 운영 패턴으로 가능.

재학습 **실행**은 off-box(KFP/MLflow) 몫 유지가 옳다. 프레임워크의 남은 몫은 **재료**(신뢰할
수 있는 알람 + raw 데이터 + 버전 연동) 생산이다.

## 보강 우선순위 (구현 순서)

| 순위 | 항목 | 이유 |
|---|---|---|
| 1 | A1 탭 재연결(자기치유) + 탭 생존 export | 감시 공백이 조용히 생기는 최악 시나리오 차단. R4 선행조건 |
| 2 | A3 NaN 집계 + 데이터품질 알람 (ABI v2, A5 예약 포함) | 실무 오탐/미탐 최대 원인 |
| 3 | R1 샘플 링 (raw 보존 + 알람 덤프) | 없으면 재학습 루프 불성립 |
| 4 | A4 severity 번들화 + 디바운스 | 알람 신뢰도 |
| 5 | A2 다모델 탭 + 출력 E2E + R2 drift_kind | 완결성 |
